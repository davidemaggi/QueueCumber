# Ackbar 1.0 implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline. The maintainer authorized the whole 1.0 milestone continuously and will perform the external acceptance checks afterwards.

**Goal:** Prepare QueueCumber 1.0.0 Ackbar for maintainer acceptance, with complete local hardening and honest release gates.

**Architecture:** Preserve the approved Electron/React utility-process design and existing broker semantics. Tighten the existing desktop trust boundary, keyboard access and narrow inspection layout; freeze documented portable formats without rewriting encrypted data. Distribution stays post-merge GitHub Actions with fail-closed Windows and macOS signing.

**Tech:** Existing TypeScript, React, Electron, SQLite, Vitest, Playwright and electron-builder 26.

**Spec:** [Approved project proposal](../../PROJECT_PLAN.md), [product](../../../PRODUCT.md), [roadmap](../../../ROADMAP.md). The user explicitly owns platform/cloud/signing acceptance after implementation; unchecked external gates do not block local preparation or authorize publication.

## Constraints and decisions

Work in place on development as requested. Preserve unrelated skill files. No push, merge, tag, account provisioning, packaging outside Actions or publication. Set package version 1.0.0 and releaseName Ackbar; this is prepared source, not a published or certified release. Package-manager submissions remain after real release assets exist, per the maintainer's earlier instruction. Native/manual assistive-technology and real keystore tests must stay accurately distinguished from DOM/keyboard automation.

## Review focus

- Renderer permissions, navigation, frames and malformed/concurrent IPC must fail closed without secret-bearing errors.
- Keyboard users must reach virtualized messages outside the first viewport without jumping over entries.
- Narrow windows must allow reaching all capture controls, list and detail without clipped panels.
- macOS distribution must not silently skip signing/notarization when credentials are absent.
- Existing encrypted data and configuration formats must remain usable; unsupported future databases must fail before schema writes.
