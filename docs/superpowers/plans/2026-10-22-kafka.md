## Design

Use the existing privileged utility, encrypted storage, bounded exports and React shell for a second provider. Kafka profiles discriminate by provider, with bounded bootstrap brokers, verified TLS/custom CA and SASL PLAIN/SCRAM credentials. Legacy RabbitMQ profiles remain accepted unchanged. Connection transfer gains a versioned schema for both providers; keep reading v1 RabbitMQ files and explicitly refuse newer versions in older apps.

Kafka topics and partition metadata use a pure TypeScript client. Direct, public fetch/list-offsets APIs explicitly target partitions; never start group-based consumption or invoke any commit API. Preserve 64-bit offsets as decimal strings, keys/null values and repeated binary headers in encrypted records/exports. Keep Kafka timestamps separate from local capture timestamps.

A finite selected partition set (maximum 128) has individual earliest/latest/specific start choices. Sequential bounded fetches provide backpressure and feed the existing finite admission/storage budgets. Poll current metadata/ranges; expose retention clamps, log truncation/topic recreation and partition-set changes. New partitions require an explicit new capture; existing selections are not silently expanded. Retry transient network/leader failures with bounded backoff; authentication/authorization and missing topics fail with a visible action-required state. Cancel/Quit closes all clients and prevents retries.

Retain the current UI design. Add provider-aware connection fields, topic filters and a compact partition position table. Reuse message detail, paging, export, tray and history. English/Italian and light/dark/narrow checks apply. No credential reloading into the renderer.

Release artifacts build only on merged pull requests into main (`pull_request_target.closed` with merged/base guards). Remove workflow_dispatch and tag/development triggers. Build the immutable merge SHA, derive v-prefixed SemVer from its package metadata, enforce main ancestry, preserve Azure fail-closed signing and create a GitHub Release draft after every target succeeds. Normal development/PR compilation checks remain separate from distribution packaging. Require version bumps before release merges; never overwrite an existing tag/release.
